# Changelog - GhidraMCP-next

Complete version history for the GhidraMCP-next project.

---

## Unreleased
### Added

- Added `set_repeatable_comment` to replace or clear repeatable listing comments at exact ordinary or overlay addresses without creating functions or other program artifacts.
- Added `apply_memory_image`, which requires an explicitly named existing program and atomically applies a fully preflighted set of initialized ordinary/overlay blocks plus optional string-valued capture metadata stored durably in Program Information. It accepts native byte arrays or hexadecimal strings, preserves preview/commit plan parity, and supports only conflict-free creation or `replace_exact` of a same-name, same-range initialized block. Exact replacement writes in place, preserving analysis, references, and file provenance while updating the requested block metadata; partial overlaps roll the whole request back, and omitted metadata preserves the stored capture record.
- Added `search_6502_indexed_operands`, a read-only, bounded instruction-aware search for absolute X/Y-indexed 6502 memory operands in explicitly qualified source and target ranges. Rows classify READ, WRITE, and READ_WRITE access, report every reference in the exact operand slot with overlay-aware status, and include a directly usable `batch_update_references` dry-run request.
- Added `find_split_pointer_partners`, a read-only bounded search for the missing half of a known split 16-bit pointer table. It tests both low/high and high/low layouts under a fixed byte-pair work cap, labels its numeric results as false-positive-prone hypotheses, and returns directly usable `apply_data_regions` region proposals.

### Changed

- `tools/release` now refuses when HEAD is already tagged `v<version>`, instead of reporting nothing to release and exiting 0.

### Fixed

- `create_memory_block` and symbol-profile memory-block application can now add a non-overlapping block to an explicitly qualified existing overlay when `overlay=false`, with identical preview/commit descriptors. `overlay=true` at an overlay address remains rejected as unsupported nested-overlay creation.
- `disassemble_flow` commits now continue through repeated-byte instruction runs exactly as preview does. Ghidra's stock repeat-pattern guard previously stopped after 16 identical instructions, causing valid plans to diverge and roll back.

## 0.100.0
### Removed

- **Breaking:** Removed the headless-only `archive_project`; use the shared `export_project_archive`.
- **Breaking:** Removed `deploy --test` and its benchmark, contract, catalog, debugger, multi-program, negative, and release modes; removed `GHIDRA_MCP_DEPLOY_TESTS`, static endpoint catalogs, benchmark fixtures, and repository/build/setup/configuration/deployment/release contract tests. Retained tests exercise shipped runtime behavior only.

### Added

- Added `export_project_archive`, which saves and exports the active GUI or headless project through Ghidra's native GAR writer. It takes one absolute `output_path`, verifies the completed GAR, and safely replaces an existing destination only after export succeeds.
- `tools/release` now accepts an exact `X.Y.Z` release version as well as `major`, `minor`, or `patch`, and no longer runs test suites before building and publishing a release.

### Fixed

- `export_full_listing` now emits authored comment lines without trailing spaces or tabs. A blank line previously rendered as `; `, so an otherwise clean generated listing failed `git diff --check`; blank offcut lines also retained the separator after their location marker, and function-variable comments could reintroduce the same defect. Empty and whitespace-only listing-comment lines remain present as bare comment lines (or an offcut marker); zero-content variable comments are omitted; other variable-comment content is normalized consistently with EOL-comment output. Multiline variable comments now continue on aligned assembly-comment lines instead of emitting raw physical lines. Other control bytes remain verbatim and remain covered by the completeness audit, including PETSCII colour and cursor codes `$1C`–`$1F`.
- `apply_symbol_profile` now treats Ghidra's generated dynamic primary label as the absence of a stored definition when a profile requests a real primary label at that address. Under the default error policy the generated name was reported as `different primary symbol already exists`; under the replace policy the planner advertised a replacement, but dynamic labels have no database record and cannot be deleted through `Symbol.delete()`, so commit rolled back with `failed to replace symbol BYTE_*`. Planning now matches Ghidra's supported `createLabel` path, which retires the dynamic label automatically; dry-run and commit agree without requiring replacement authority for a definition that does not exist.
- The real-Ghidra scoped-analysis fixture now retains and joins the headless analysis worker before final scheduler assertions and before disposing its program on a failed assertion. Seeing the expected function proved that the asynchronous worker had started, but an immediate `AutoAnalysisManager.isAnalyzing()` read could race with it after the status poll. `analysis_status` remains a non-blocking point-in-time observation: `analyzing=false` does not promise that a separately queued analysis transaction has closed or finished flushing events.
- `disassemble_flow` commits now give every planned direct-call subtree its own commit root when `follow_calls=true`. The frontier previously rooted only the normalized seeds and flows out of pre-existing instructions, so a wholly new callee had no root and the commit depended on Ghidra's stock traversal rediscovering it from the caller; where it does not, the endpoint detects a preview/commit divergence and rolls back otherwise valid disassembly. Commit roots are also restricted to planned instruction starts, so an unfollowed call whose operand lands inside another planned instruction cannot become an off-cut disassembly seed.
- `apply_data_regions` now resolves fixed well-known datatypes such as `byte`, `word`, and target-sized `int` even when a pristine program has not registered them, restoring split-pointer tables on fresh 6502/C64 imports and preserving the target program's data organization. Split source bytes no longer depend on caller-visible datatype lookup. Before a cloned built-in reaches Ghidra's destructive canonical-path resolution, the endpoint now reuses an equivalent program datatype, preserves compatible fixed one-byte program occupants for split sources, or rejects an incompatible occupant with the requested name or split-source usage, canonical path, occupant length, and remediation; this also protects case variants and aliases such as `BYTE` and `uint8` resolving to an occupied `/byte`.
- The real-Ghidra manual-control-flow fixture now keeps its ordinary direct-jump target separate from the jump table it later types and explicitly restores the table bytes to their intended raw state after instruction setup. Once another fixture had loaded Ghidra's analyzer extensions, disassembling the fixture's `JMP ($2000)` could classify its pointer operand at `$2000` before `describe_jump_table` ran, making the full suite order-dependent and fail with a code/data conflict even though the control-flow implementation was unchanged.
- The real-Ghidra `get_references_into_range` aggregate-data regression fixture no longer tries to create a second memory block over an address already covered by its `.text` fixture block. The overlap made the otherwise valid renderer test fail during setup on Ghidra 12.1.
- `export_full_listing` no longer falsely rejects programs with external entry points. Ghidra represents each one as a synthetic reference whose source address renders as `Entry Point`; the completeness audit split reference tokens on spaces and therefore searched for two fragments instead of the emitted `Entry Point(*)`. The audit now parses the comma-delimited reference groups and their wrapped continuation lines, preserving spaces inside address text while retaining its artifact-level loss check.
- `debugger_launch` can now set the offer-specific parameters published by `debugger_launch_offers`. The endpoint previously hard-coded only executable, argument, working-directory, and Python fields, so connector offers could expose parameters such as VICE's `env:OPT_PRG_FILE`, `env:OPT_PORT`, and `env:OPT_EXTRA_VICE_ARGS` without any MCP call being able to supply them; launching VICE over MCP therefore always used the saved/default machine state. The new optional `launcher_args` JSON object is keyed by the exact published parameter names, accepts scalar string/number/boolean values, validates every key against the selected offer, and passes the values through Ghidra's own typed launcher decoder. Explicit `launcher_args` values override the endpoint's convenience fields and the offer's saved/default values.
- `apply_symbol_profile` can now plan a profile's symbols and comments inside the memory blocks that the same profile creates. A profile declaring the C64 hardware and KERNAL blocks at `$D000-$FFFF` and naming the registers inside them failed against a program whose memory stops at `$CFFF`, with `Failed to apply symbol profile: invalid symbol address: Address is not mapped in program memory: d000` — even with `create_memory_blocks=true` **and** `dry_run=true`, so the caller could not preview what the endpoint would do without committing, and committing failed identically. The cause was ordering: `plan` resolved namespaces, symbols, equates and comments *before* `planBlocks`, so every address was validated against memory as it stood rather than as the plan would leave it. Blocks are now planned first, and the ranges of the blocks whose action is `create` are threaded into the address resolution the other planners use, as an explicit `additionalMapped` argument on `AddressCommentCore` that defaults to empty — no other caller's validation is weakened. Application is reordered to match, creating blocks before the symbols and comments that land in them. Only blocks actually being created count, so `create_memory_blocks=false` still rejects an address in a declared-but-uncreated block exactly as before and still reports the `memory_blocks were validated but creation is disabled` warning; overlay blocks are excluded, because an overlay maps a new address space rather than the base one; and an address in no block at all still fails with the unchanged message. Equate applications are unchanged in effect — a freshly created block holds no instructions, so an application inside one is still refused, now with the accurate `is not an instruction` rather than a misleading unmapped-address error.
- **Breaking:** mutating endpoints now refuse an unqualified address whose offset is mapped in more than one address space, instead of silently writing to the default physical space. Only the comment endpoints carried this check; everything else called `ServiceUtils.parseAddress` directly and got no guard, so on a program with an overlay block `set_plate_comment` at `9762` correctly refused with "Ambiguous unqualified address '0x9762' maps to multiple program address spaces: [9762, SND_PLAYER::9762]. Use a qualified `<space>:<hex>` address", while `create_label` and `apply_data_type` at the same address quietly succeeded — against the other occupant. That is the whole harm: the two occupants of an overlapped offset are different code or data (on the motivating target, a resident disk loader in RAM and the recovered sound player that displaced it at runtime), so a mutation aimed at the overlay lands on the physical occupant and corrupts the analysis of the one the caller meant, with no error, no warning, and nothing in the response distinguishing it from having worked. The check moved out of `AddressCommentCore` into `ServiceUtils` — `ambiguousUnqualifiedAddressError`, `parseMutationAddress`, `probeMutationAddressAmbiguity` and `firstAmbiguousUnqualifiedAddress` — so there is one implementation and one message rather than a rule enforced in one corner of the codebase. It now applies to `create_label`, `delete_label`, `rename_label`, `rename_or_label`, `rename_data`, `rename_external_location`, `batch_create_labels`, `batch_delete_labels`, `apply_data_type`, `apply_data_classification`, `set_global`, `set_decompiler_comment`, `set_disassembly_comment`, `clear_function_comments`, the per-line addresses in `batch_set_comments`, `add_memory_reference`, `remove_reference`, `write_memory_bytes`, `patch_bytes`, `undefine_range`, `disassemble_flow`, `set_bookmark`, `delete_bookmark`, `set_image_base`, `create_function`, `delete_function`, `clear_flow_and_repair`, `set_function_prototype`, `set_local_variable_type`, `set_parameter_type`, `set_decompiler_variable_type`, `set_function_this_type`, `set_function_no_return`, `set_variable_storage`, `set_variables`, `rename_variable`, `rename_variables`, `rename_function_by_address`, `batch_rename_function_components`, `add_function_tag`, `remove_function_tag`, `batch_add_function_tags` and `batch_remove_function_tags`, alongside the comment, reference, entry-point, jump-table, self-modified-operand, data-region and symbol-profile paths that already had it through `AddressCommentCore`. Batch endpoints check every address before opening their transaction and fail the whole request naming the offending one, so a partially applied batch is not a possible outcome. Parameters that may carry a function *name* rather than an address are probed rather than parsed, so a name still resolves. `set_image_base` additionally moves its address resolution out of the Swing lambda, where the thread-local parse error it reported was invisible to the caller, and `apply_data_type` now returns a refused mutation as an error rather than as plain-text output. **Reads are deliberately unchanged**: a bare hex address still resolves to the physical space on every read-only endpoint, which is the documented convention, and a regression test pins it. Four mutating memory-block parameters are also deliberately unguarded — `create_memory_block`'s `start`, `split_memory_block`'s `split_address`, `move_memory_block`'s `new_start` and `resize_memory_block`'s `new_end` — because each either places a block that does not exist yet or is scoped to a named block whose space mismatch is already rejected outright, so no bare offset can silently select the wrong occupant.

### Added

- `batch_update_references` now round-trips every reference type Ghidra considers valid for a memory reference, including `READ`, `READ_WRITE`, their indirect forms, conditional flows, parameters, and override references. Adds remain restricted to `RefTypeFactory.getMemoryRefTypes()`, while removals accept any public `RefType` field or emitted name so existing analyzer and legacy references can be named exactly; the non-user-removal gate, dry-run preview, primary validation, and atomic transaction remain unchanged. Response type names are valid input for a later request, including Ghidra's `EXTERNAL_REF` / `EXTERNAL` mismatch. Explicitly qualified in-bounds overlay targets remain in the overlay, while an offset outside its block is rejected rather than silently landing in the base-space occupant. The four override reference types can intentionally alter decompiler call/jump interpretation as well as navigation and should be used only when that semantic override is intended.
- Added `audit_stale_comment_names`, a read-only whole-program audit for Ghidra-generated address names that remain in listing comments after the addressed code or data receives a meaningful symbol. It scans all five comment kinds in mapped memory, resolves both default-space and overlay-qualified dynamic names through Ghidra, suppresses names that are still current or whose targets have only generated symbols, and reports the current primary name plus aliases. Results are deduplicated, deterministically ordered, paged, tied to a program modification number, and include a Unicode-safe excerpt centered on the stale mention. Deliberate historical mentions can still be reported and require human review; deleted labels with no resolvable generated address are outside the audit's scope.
- Added `analyze_coverage`, which answers "how many bytes are still unexplained, and where" for the whole program. Nothing in the API could answer it: `find_code_gaps` and `find_next_undefined_function` both report what is not covered by a *function body*, so a project that deliberately creates no function objects — labels, comments and data only, a recurring convention for 6502 snapshots — has its entire image reported as a gap. Deriving real coverage on the motivating target meant exporting a 953 KB listing and parsing every code-unit line by hand; the answer was 30,020 of 53,888 bytes undefined, in 28 runs, none of them in the project's own documented list of unknowns. The endpoint classifies every initialized byte as instruction, data or undefined per address space, with the three always summing to the space total, and reports the undefined runs themselves: length, preceding and following labels as objects carrying address, name and distance (or `null` at a block edge), the primary labels *inside* the run inclusive of its first and last byte, and the number of references landing in it. Classification uses `Undefined.isUndefined(dataType)` and never `Data.isDefined()`, which returns true for an explicitly applied `undefined1`…`undefined8` and would report exactly the bytes this endpoint exists to surface as data — on the motivating target that mistake splits the largest unclassified region into three and shrinks it from 21,427 bytes to 17,418. Initialization comes from `Memory.getAllInitializedAddressSet()` rather than `MemoryBlock.isInitialized()`, which is false for byte- and bit-mapped blocks whose bytes are initialized; the uninitialized remainder is reported separately in `uninitialized_ranges` and never counted as undefined. Runs close at both kinds of boundary — every memory-block boundary, even where adjacent blocks coalesce inside an address set, and every initialized-range boundary inside a block — so a run never merges two blocks or bridges a hole. Overlay spaces get their own row, since a blended percentage is meaningless on a banked target. A second namespace, `annotation_backlog`, tallies generic symbol prefixes (`DAT_`, `SUB_`, `LAB_`, `FUN_`, `UNK_`, configurable) and unknown markers — labels and comments of every type carrying a configurable prefix, `TODO` by default, because hard-coding one project's convention would import it into a tool that knows nothing about the project. Exact byte facts and convention-based audits are kept in separate namespaces on purpose: they are different kinds of claim and must not read as one metric. Statistics are always whole-program, and `undefined_runs` and `unknown_markers` page independently, each with its own `offset`, `limit`, `returned` and `has_more`; there is no top-level `truncated`, which would conflate rows skipped before the page with rows remaining after it. The listing is walked by merging the instruction and defined-data iterators and deriving the gaps arithmetically, never through `listing.getCodeUnits`, which synthesizes one unit per uncovered address and would make the walk proportional to every undefined byte. The read spans several passes, so the modification number is pinned before and checked after: a program edit landing mid-read fails the call rather than returning mixed numbers, and the number is echoed so two pages from different revisions are detectable.
- Added `search_address_encodings`, which finds byte windows that numerically decode into a destination address range whether or not Ghidra recorded a reference — untyped pointer tables, operands the analyzer left unresolved, pointers sitting in undefined bytes. `get_references_into_range` reports what the reference database holds and says so; this is the independent pass that closes that blind spot, and the two are separate endpoints because they answer different questions with different parameters. The destination range fixes which rows can appear, and `matching_references` counts a reference only when its destination equals the decoded target in **both space and offset**, so on an overlaid program a RAM query and an overlay query over the same offsets return different references — the overlay query shows the player call with its reference and the disk-loader window with an empty array, and the RAM query inverts exactly that. Each row reports where the window sits as `inside_instruction`, `inside_data_unit` or `undefined`, deliberately not as an operand claim: a window beginning inside an instruction may start on the opcode or straddle a code-unit boundary, and Ghidra's API does not portably map operand indices to byte spans, so `matching_references` carries the semantic evidence instead. Reference origins are defined for all three site kinds — the instruction start, the containing primitive component's start for a data site (a dispatch-table entry, not the whole array), and the encoding address itself when there is no containing unit. Widths of 1 to 8 bytes and both byte orders are supported, decoded through unsigned `BigInteger` so no width is a special case, and a destination bound not representable in the chosen width is rejected rather than silently producing an empty result that reads as a clean sweep. Every offset is tested, unaligned included, and overlapping windows are separate rows, because either could be the real operand. Paging uses an HMAC-authenticated cursor rather than an offset, since the traversal itself is the expensive part: the page is established by finding one match beyond it, and *that* match's own address is bound as an inclusive resume point, so the lookahead row is returned as the first row of the next page instead of being lost, and a run that ends exactly on the page boundary returns `cursor: null` rather than a trailing empty page.

### Changed

- `tools/release` now exits successfully when HEAD already carries its release tag, reporting that there is nothing to release rather than failing. A release tags its own commit, so a tagged HEAD is the record that this commit was released — and until now a re-run over one was an error: either `ensure_tag_absent` refused, or `resumable_version` fired first and re-attempted `gh release create` for a release that already existed, which fails. That is what made a sweep over several repositories unrepeatable, and `~/code/scripts/release_ghidra_tools` (which runs this script alongside the connector's and c64-mcp's) depends on the skip: a repository with nothing new is a no-op, not a failure that stops the sweep. Only `v<semver>` tags count, so neither this repository's `build-*` tags nor the older upstream `v1.x`–`v6.x` line at other commits can be mistaken for a release of the current version line. The publish-only resume path is removed with it: a publish that fails after the push now leaves a tagged HEAD that reads as released, so finish that case by hand with `gh release create` — no local state can distinguish it from a completed release, and guessing wrong in the other direction would re-publish.
- **Breaking:** `search_byte_patterns` returns an object instead of a bare array, and its response shape has changed. The old array carried truncation and empty-result notices *as elements* — `{"note": "Limited to 1000 matches"}` and `{"note": "No matches found"}` — which a naive consumer counts as matches. Now `matches` is a plain array (empty is data, not a note) inside an envelope with `total_matched`, `returned`, `limit`, `offset`, `has_more`, the echoed `pattern` and `effective_mask`, a `wildcard_count`, a `scope` block naming the searched spaces, and `program_modification_number`. Four real defects are fixed with it. The declared `mask` parameter was accepted and completely ignored; it is now honoured with Ghidra's bit-mask semantics, ANDed with the wildcard default so neither mechanism can re-enable a bit the other waived, and echoed as `effective_mask`. `start`/`end` scope a search to one inclusive range in one address space, with the *whole* match required to fall inside it. The old implementation read each block into a single `byte[]` and skipped a failed `block.getBytes` with a bare `continue`, so a count presented as exact could silently omit an entire block; the new bounded chunk scanner reads fixed-size chunks with pattern-length overlap and reports a read exception *or* a short read as a structured error naming the block and address. It deliberately does not use `Memory.findBytes`: that API catches its own read errors and returns null, making a failure indistinguishable from a miss, and it constrains only a candidate's start against the end address. Ordering is total — address-space name, then offset — and defined before paging, so `offset` means something; paging streams rather than accumulating, since an all-wildcard pattern matches at nearly every offset. A program edit landing mid-scan fails the request rather than returning a total that was never true of any single program state. One related claim is retracted: a project note that the endpoint "returned a single hit for `20 ?? 97` when several exist, so it does not match exhaustively" was retested against the program it was written about and is false — it returns all 14 matches, 11 in RAM and 3 in the overlay, each correctly space-qualified.
- The `search_byte_patterns` annotation now declares category `search` rather than `analysis`, matching `tests/endpoints.json`, which already carried `search`. The catalog value was the better one, so the annotation moved to it rather than the catalog being regenerated to the drift.
- **Breaking:** `get_references_into_range` replaces its `truncated` flag with `offset` paging. A single address carrying more than `limit` incoming references previously had no route to the rest: the flag announced incompleteness without offering a way out. The response now carries `offset`, `limit`, `returned` and `has_more` alongside the unchanged whole-range `count`, plus `program_modification_number` so two pages taken from different revisions are detectable rather than silently stitched. A negative `offset` is rejected rather than clamped, and `offset + returned` is computed in long arithmetic so a near-maximum offset yields an empty page instead of a wrapped `has_more`. The implementation already collected and sorted the whole result, so the page is a slice of it and `count` stays exact.

### Changed

- Renamed the bridge Python package `bridge_mcp_ghidra` to `ghidra_mcp_bridge` and its console script `bridge-mcp-ghidra` to `ghidra-mcp-bridge`, matching the wheel, which was already `ghidra-mcp-bridge`. The same three words previously appeared in three different orders across the wheel, the package and the script. **This changes the command MCP clients launch**: update any `.mcp.json` entry from `bridge-mcp-ghidra` to `ghidra-mcp-bridge`, and re-sync the virtualenv so the old script is replaced.

### Added

- Added `tools/release <major|minor|patch>`, replacing the retired CI release job. One command: it refuses unless the checkout is on the default branch, clean and exactly in sync with `origin`, then writes the version, rolls the changelog, runs the full gate set against that release candidate, builds and inspects the artifacts' contents, commits, tags, pushes, and creates the GitHub release — in that order, so a gate sees the mutation it exists to catch and everything that can fail runs before the push. A failure before the push restores the working tree, the index and the branch ref, so it is a no-op rather than a mess to unpick; a pushed tag cannot be retracted, so re-running the same command reports that tag as released rather than bumping again. Every `gh` call is pinned with `--repo` derived from `origin`, because `gh` otherwise resolves through `upstream` in this repository — a different project entirely. Publishing verifies the peeled remote tag points at the released commit and that each artifact still hashes to what the build produced, so an artifact rebuilt from another commit cannot be published under the same version.

### Changed

- Versioning moves from build timestamps to semantic versions, starting at `0.99.0`. The extension zip is now `GhidraMCP-next-<version>.zip`, `app.version` and `Plugin-Version` carry the project version, and `extension.properties` gains `pluginVersion` alongside the `version` field Ghidra owns and gates installation on. `build.timestamp` and `build.number` remain real build timestamps: they are surfaced through the bridge handshake, and a field named `build_timestamp` holding a semantic version would lie. The bridge wheel now takes the same version from `pom.xml` rather than deriving its own PEP 440 timestamp, so one release carries one version — and that also removes a latent defect, since PEP 440 strips leading zeros from release segments and a bridge built between 00:00 and 09:59 UTC produced a version its own validation then rejected.

### Added

- Added `get_references_into_range`, listing every recorded reference whose destination falls in an inclusive address range, as a flat list ordered by source address. The question "which references land anywhere in this span" had no expression in the API: answering it for a 640-address overlay window previously meant four `get_bulk_xrefs` calls over a hand-generated list of every address in the range. Each row carries the source, a symbol naming it, a `from_symbol_relation` of `at`/`containing`/`preceding`, the rendered instruction or code unit, the destination, the reference type, the source kind (`user_defined`/`default`/`analysis`/`imported`/`ai`) and the operand index — enough to classify a site and then act on it with `remove_reference` or `add_memory_reference` without a second call per row. Containment and proximity deliberately use different field names: `from_symbol` with `from_symbol_offset` appears only when the offset really indexes into the named thing (`at`, `containing`), while the nearest-label guess is `nearest_preceding_symbol` with `nearest_preceding_distance`. One field plus a qualifier was not enough, because a caller reading only `from_symbol` could still print `PART_FILENAME+475` for code 475 bytes past a five-byte buffer — the preceding-symbol walk is bounded only by the memory block, which on a program laid out as one 53 KiB block never bites. On a labels-only program this is every row, not an edge case: with no Ghidra functions there is no `containing` match at all. `from_instruction` renders through the same `CodeUnitFormat` configuration the full-listing exporter uses rather than `CodeUnit.toString()`, one operand at a time, so an operand resolves to its symbol across address spaces — `JMP SND_PLAYER:SND_V1_STREAM_ADVANCE3`, not `JMP 0x97a9`, which on this endpoint is the difference between answering "which occupant does this site mean" and restating the bytes. Rendering the whole code unit in one call does *not* resolve cross-space operands, and the per-operand form is what does. A reference recorded from the interior of an aggregate renders the primitive at that offset instead of the whole array, so a dispatch-table entry reads as `dw 96A1h` rather than a bare `dw[15]`. Ordering by source rather than destination keeps the two halves of one page-copy loop adjacent, and an indexed store contributing two destination references appears as two adjacent rows sharing a source rather than under two separate keys. Addresses are space-qualified whenever the program has any overlay or more than one physical space; `ServiceUtils.addressToJson` could not be reused for this because `getPhysicalSpaceCount` excludes overlays, so on a one-physical-space-plus-overlay program — the exact shape this endpoint exists for — it would have emitted bare hex and lost the distinction the query is asked to make. `resolved_range` always echoes the range fully qualified, and `overlapping_spaces` always lists the other spaces occupying those offsets (`[]` when none), computed from memory *blocks* rather than address-space bounds: an overlay space spans the full range of the space it shadows, so a space-bounds intersection would name every overlay on every query. That list is symmetric — a physical query names the overlays, an overlay query names the physical space and any sibling overlay — and never includes the queried space itself. Offsets are compared as `BigInteger`, so high-half 64-bit ranges do not mis-order. `count` reports total matches even when `limit` truncates the returned rows, with `truncated` marking that it did. Every response also carries `scope: "recorded_references_only"`, because the completeness boundary has to survive being read without the tool description in view — a stored result saying `count: 7` reads as "there are 7" unless the response itself says what was counted. That boundary is stated narrowly on purpose: the result is complete for what Ghidra's reference database currently holds, and silent on bytes that encode an in-range address without a recorded reference — untyped pointer tables, computed targets, operands the analyzer left unresolved. No single follow-up pass closes the gap, since decoding instructions finds missed control flow but not untyped data pointers, so a wider sweep raises confidence rather than proving exhaustiveness. Verified against a real overlay program: a physical query over the shared range returned exactly the seven references a hand-built sweep had found, an overlay query over the same offsets returned only the other occupant's, and `limit=5` reported `count: 93` with `truncated: true` rather than passing the cap off as the total.

## GhidraMCP-next 20260725-220621

### Added

- Added `export_full_listing`, a complete listing export that drops nothing. `export_ascii_listing` delegates to Ghidra's `AsciiExporter`, which loses material four ways: `clip()` on width-constrained fields, a hardcoded six-line ceiling on EOL comments, a hardcoded twenty-one direct reference ceiling, and stack-variable widths its option list never publishes. Measured on a real 6502 program, a whole-program Ascii export clipped 1164 lines and emitted 21 of the 28 references to one address behind an `XREF[21]` header that misreported the total. This endpoint has no clip step and no ceilings: every authored comment line survives, every reference is listed, offcut annotations are emitted in their own labelled group, and columns are minimum widths so a long operand pushes the comment column right instead of being shortened. Authored newlines are never re-flowed, so aligned tables and diagrams survive. Operands render through `CodeUnitFormat`, keeping symbol substitution and overlay block qualification — `get_listing_range`'s `operand_text` is deliberately raw and would emit a bare address instead. The export fails without publishing if it cannot emit everything it collected, so a future Ghidra release adding a comment kind produces an error rather than a quietly incomplete artifact. Annotation gathering reuses `ListingRangeService.RangeIndex`, already driven from the comment and reference address iterators that make offcut positions visible. No timestamp is written, so repeated exports of an unchanged program are byte-identical and diffable. Like `export_ascii_listing`, it takes no explicit read lock, so both have the same exposure to a concurrent edit. Structures and arrays are traversed, so field names, component types and values appear indented under their parent; an element of a scalar array is not restated, since the parent's byte column already prints every byte of it unclipped. Completeness is checked against the written file rather than against internal counters: every authored comment body line and every reference must be found in the output, so a renderer that emits part of a body, a deleted call to the reference writer, or a sink that silently swallows a line fails the export instead of publishing. A program edit landing mid-export fails it too, the modification number being pinned before any model read.
- Added `diff_memory`, comparing two equal-length ranges that may live in different address spaces — an overlay against the block it shadows — and returning the differing byte runs. Establishing where two occupants diverge previously required reading both ranges out in full and diffing them externally. Only differences are returned, since the gaps between them are equal by construction; `differing_bytes` and `difference_run_count` describe the whole comparison even when the returned list is clipped by `max_runs`.
- Added `get_comment`, returning every listing comment kind (plate/pre/eol/post/repeatable) at any address, plus the first non-empty one and a `has_comment` flag. `get_plate_comment` requires a function, so a comment attached to a data address could not be read back at all. Adapted from upstream `c0d1fb8`; only `get_comment` is taken, and it is reimplemented against Ghidra 12.1's `CommentType` enum because upstream's version calls the removed `CodeUnit` int constants.
- Added `rename_data_type`, renaming a type in place and preserving its existing applications; the previous route of clone, re-apply and delete dropped them silently. Adapted from upstream `0b85f41` with stricter name resolution: qualified names resolve by exact category path, and an ambiguous bare name is refused with the candidate paths listed rather than resolving to whichever type is found first.

### Fixed

- `batch_set_comments` no longer skips malformed items in silence. An item with an unrecognised key, a missing `address` or `comment`, or an unresolvable address previously left the call reporting success with a zero count; every problem is now reported with its field and index, and the request writes nothing. The two arrays are decoded strictly at the wire boundary, so a non-object array element or a non-string `address`/`comment` is rejected rather than dropped or stringified into the comment text, and both the native-array and stringified forms go through the same decoder.
- `batch_update_references` can now remove references whose target address is unmapped, matching `remove_reference`. Such edges are created by Ghidra itself when a computed jump's operand is patched at runtime, and are exactly the ones worth deleting. A removal that matches nothing now also lists the references actually present at the source address.
- `list_instances` no longer returns every program in the project. The roster is replaced by a count plus the open programs, capped with an explicit truncation remainder; upstream measured ~90KB for 626 programs, past MCP result limits. Adapted from upstream `2b2f8fa`.
- `check_tools` distinguishes "no schema loaded" from "no such tool". Every Ghidra tool was previously reported `not_found` when no instance was connected; unconnected lookups now return `unknown` and name the fix.
- The Maven build fails immediately when run on a JDK that cannot build the project, naming both the running and required versions. Previously JDK 26 produced a wall of compiler output ending in `warnings found and -Werror specified`, with nothing indicating the JDK was at fault. The required version is read from the pom rather than hardcoded.
- CI now runs the `com.xebyte.core` Java tests, which no test-selector matched and which therefore never executed.
- Allowed `debugger_launch` to use connector offers that take no executable. `executable_path` is now optional: offers exposing no image parameter — connectors that attach to an already-running emulator or stub — previously failed outright, since the launcher unconditionally required one. Supplying a path to such an offer, or omitting it for an offer that does launch an executable, is reported explicitly rather than ignored. With this the VICE C64 connector launches end to end over MCP.
