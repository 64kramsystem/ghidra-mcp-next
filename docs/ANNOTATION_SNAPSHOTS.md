# Annotation snapshots

`export_annotations` writes a deterministic JSON snapshot of user-defined and imported labels and function names, listing comments, defined data, instruction coverage, and opaque data markers. It records the original executable SHA-256, language, compiler, image base, mapped blocks, overlay bases, and initialized-byte digests. Paths obey `GHIDRA_MCP_FILE_ROOT`. An existing snapshot is replaced only with `overwrite=true`; replacement rejects lost comment slots, symbol aliases, data or instruction coverage, and opaque markers unless `allow_loss=true`. Renaming symbols, editing comments, and changing data types without losing coverage are not losses. The response includes any allowed losses.

`import_annotations` requires the same original source and mapped bytes. It overlays data definitions, labels, comments, and opaque markers in one transaction, reports overwritten values, and leaves unmentioned annotations alone. Named data types refer to the target program’s existing type at the exact path, or to a Ghidra builtin; the snapshot does not verify custom type definitions. Arrays and pointers describe their element or target type. Existing conflicting code or data is not cleared. A function name becomes a label if there is no function at that address. Instruction coverage is evidence for export loss checks; import does not create or require matching instructions or functions. The import does not save the program.

Snapshots do not contain memory bytes, instructions, functions, references, equates, datatype libraries, decompiler locals, or function signatures. Use a project archive when those are needed.

The version 1 file has `format`, `schema`, `source`, `view`, `symbols`, `comments`, `data`, and `instructions` fields. Addresses use `{ "space": "ram", "offset": "1000" }`, with unsigned lowercase hexadecimal offsets; ranges add a byte `length`. A block adds `initialized`, a SHA-256 for initialized bytes, and `overlay_base` for an overlay. A symbol adds `namespace` (an array of components), `name`, `kind` (`label` or `function`), `source`, and `primary`. A comment adds `kind` and `text`. A data record adds `type` and `opaque`. Instruction records are ranges.

A named type is `{ "kind": "named", "path": "/byte" }`. An array is `{ "kind": "array", "element": <type>, "count": 4 }`; a pointer is `{ "kind": "pointer", "target": <type or null>, "length": 8 }`. The `source` object contains `sha256`, `language`, and `compiler_spec`; `view` contains `image_base` and `blocks`.
